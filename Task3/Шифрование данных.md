# Шифрование данных

### Какие данные нужно шифровать

| **Данные**                                                              | **В чём необходимость защиты**                                                                                                       |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Персональные данные пациентов                                           | Репутационные риски и санкции со стороны регулирующих органов в случае утечки                                                        |
| Истории болезни пациентов, результаты анализа лабораторных исследований | Репутационные риски и санкции со стороны регулирующих органов в случае утечки                                                        |
| Персональные данные врачей и других сотрудников                         | Репутационные риски и санкции со стороны регулирующих органов в случае утечки                                                        |
| Бухгалтерия                                                             | Риск снижения финансовой устойчивости, репутационные риски, а также возможные санкции со стороны регулирующих органов в случае утечк |

### Инструменты защиты

Шифрование вышеперечисленных данных в состоянии передачи сводится к использованию протокола https путем настройки TLS-соединений между всеми компонентами системы: базами данных, микросервисами и клиентскими приложениями.

Хранить вышеперечисленные данные также необходимо в зашифрованном виде, прибегая к шифрованию непосредственно перед помещением данных в хранилища. Чтобы этого добиться, необходимо интегрировать соответствующие микросервисы с KMS-системой, которая будет хранить и ротировать ключи шифрования. Для шифрования данных в S3-хранилище стоит использовать SSE-C – вариант, при котором клиент предоставляет Amazon собственные ключи шифрования. Это позволит использовать ключи из ранее упомянутой KMS-системы вместо делигирования управления ключами внешней системе.

Для повышения безопасности конфиденциальных данных в процессе использования предлагается рассмотреть правило явного удаления чувствительных данных из оперативной памяти после их обработки в случаях, когда язык программирования позволяет это сделать. Добиться этого можно путем вндерения практики код-ревью и назначеня ответственного сотрудника, контролирующего соблюдение данного правила другими разработчиками.
