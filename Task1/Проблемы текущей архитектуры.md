# Проблемы текущей архитектуры

### Существующие проблемы

При проведении аудита текущих процессов компании были выявлены следующие проблемы:

- отсутствуют механизмы отзыва согласия на обработку персональных данных, а также их просмотра и изменения;
- не понятно, уточняется ли вообще согласие пользователя на обработку персональных данных;
- собираются избыточные данные при регистрации новых пользователей: вероятнее всего, место прописки, а также работы или учебы не нужны для предоставления медицинских услуг;
- отсутствуют механизмы управления доступом к конфиденциальным данным;
- конфиденциальные данные хранятся в открытом виде;
- не ведется журналирование операций над конфиденциальными данными;
- не делаются бэкапы и/или репликации данных.

### Что еще можно улучшить

Для обрабатываемых данных предлагается использовать следующие методы защиты:

| **Данные**                                                              | **Метод защиты** | **Комментарий**                                                                                            |
| ----------------------------------------------------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------- |
| Персональные данные пациентов                                           | Шифрование       | В открытом виде доступны сотрудникам ресепшена                                                             |
| Истории болезни пациентов, результаты анализа лабораторных исследований | Шифрование       | В открытом виде доступны врачам                                                                            |
| Персональные данные врачей и других сотрудников                         | Шифрование       | В открытом виде доступны бухгалтерам                                                                       |
| Записи на прием                                                         | Токенизация      | В открытом виде доступны сотрудникам ресепшена и врачам                                                    |
| Результаты лабораторных исследований                                    |                  | Текущий процесс предполагает, что они уже хранятся в обезличенном виде                                     |
| Инвентаризация                                                          |                  | Если не содержат конфиденциальную информацию, можно ограничиться выдачей доступа только сотрудникам склада |
| Бухгалтерия                                                             | Шифрование       | В открытом виде доступны бухгалтерам                                                                       |

В дальнейшем при необходимости получения большего контроля над данными в системе предлагается рассмотреть внедрение тегирования. Соответствие данных тегам может выглядеть следующим образом:

| **Данные**                                                              | **Тег**                             |
| ----------------------------------------------------------------------- | ----------------------------------- |
| Персональные данные пациентов                                           | Personally Identifiable Information |
| Истории болезни пациентов, результаты анализа лабораторных исследований | Protected Health Information        |
| Персональные данные врачей и других сотрудников                         | Personally Identifiable Information |
| Записи на прием                                                         | Operational Data                    |
| Результаты лабораторных исследований                                    | De-Identified Data                  |
| Инвентаризация                                                          | Warehouse Data                      |
| Бухгалтерия                                                             | Financial Data                      |

Порядок проставления меток будет зависеть от инструмента, а выбор инструмента – от того, с какой именно целью они будут собираться, от стоимости внедрения и обслуживания, а также от совместимости с другими технологиями, внедренными при автоматизации бизнес-процессов. Из вариантов, которые предлагается рассмотреть, – OneTrust и DataGrail. Оба решения усилят контроль над соблюдением нормативных требовний, что является приоритетной целью компании, и в то же время являются чуть более простыми относительно своих аналогов с точки зрения внедрения и сопровождения.
